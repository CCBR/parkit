# Release Notes: v3.2.0

## Highlights

### `parkit syncapi` / `checkapisync` follow HPC_DME_APIs release branches

`CBIIT/HPC_DME_APIs` no longer publishes GitHub tags or releases. Each release lives on a `releases/X.Y.Z` branch, and a release counts as stable once that branch is merged into `master`.

```bash
parkit checkapisync
parkit syncapi
parkit syncapi --ref 3.31.0          # pin a branch or tag (X.Y.Z = releases/X.Y.Z)
export HPC_DME_APIs_REF=3.31.0       # pin for syncapi, checkapisync and projark
```

- The default target is the **latest stable release**: the highest-numbered `releases/X.Y.Z` branch merged into `master`. Versions are compared numerically, and malformed names (e.g. `releases/1.5.2-candidate`) are ignored.
- `syncapi` switches to the target branch (or tag) instead of running `git pull`. It never creates merge commits and never downgrades automatically. It aborts on uncommitted changes to tracked files or on local-only commits.
- `checkapisync` reports the local and target release. It no longer reports a clone stuck on an old release branch as in sync.
- Both commands return meaningful exit codes: `0` ok, `1` out of sync or failure, `2` configuration error.

See [parkit syncapi](../cli/parkit-syncapi.md) and [parkit checkapisync](../cli/parkit-checkapisync.md). (#68, #69, @kopardev)
